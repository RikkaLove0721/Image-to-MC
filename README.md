# MC 工程图 · Image to MC

把一张建筑照片转成 **Minecraft Java 1.12.2** 方块模型（`.schematic`），并给出方块清单、等轴测预览与分层视图。

流程是**照片分析 → AI 写蓝图 → 本地展开成方块 → 体检 → AI 只改该改的**：
AI 不读像素、也不吐方块，只写几十行结构描述（体块 / 窗阵 / 屋顶 / 细节），
生成完再由本地把模型量一遍、把偏差喂回去，最多修 3 轮，取分最高的一版。
复杂建筑（宫殿、庄园、府邸）不会再被压成一个方盒子。

## 下载

**Windows x64 免安装版** → [最新版 Release](https://github.com/RikkaLove0721/Image-to-MC/releases/latest)

解压后双击 `MC工程图.exe` 即可，不需要另装 Python 或 Node。整个文件夹一起放，不要只拷 exe。

第一次用可以点首页的「使用说明」，里面写了拍摄要求、三个滑条的区别、
查看器的操作方式和导出步骤。

## 接入 AI / MCP

复杂建筑（别墅、多体块）走"照片直转体素"只会得到方盒子：像素能告诉你颜色，
但告诉不了你"这是主楼，那是侧翼"。所以这条路拆成三步：

```
照片 ──► brief（几十行） ──► AI 写蓝图 spec（几十行） ──► 本地展开成方块
         analyze.py            LLM / MCP 客户端              spec.py
```

**为什么省 token**：AI 不读图、也不吐方块。它拿到的是分析好的 brief，
写的是几十行的 spec（体块 + 窗阵 + 屋顶 + 材质），像素处理和体素展开全在本地。

### 闭环：AI 跑蓝图，而不是只写蓝图

一轮定稿的问题是"没人看结果"：AI 写完就走，构建器照章办事，像不像只能等
人肉看图。所以构建完会做一次**体检**（`mc12/critique.py`），把"像不像"翻成
AI 能读的数字：

| 指标 | 判什么 |
| --- | --- |
| 宽高比 | 长横的宫殿有没有被做成立着的方楼 |
| 体量 | 是不是一个长方体；多体块有没有主次 |
| 屋顶 | 大体量建筑用了平顶？孟莎屋顶太扁？老虎窗不够？ |
| 层高 | 是不是靠堆层高把楼"拉高"（最常见的错） |
| 窗阵 | 正面开间数够不够、有没有大片实墙 |
| 配色 | 主墙色和照片差了几个 ΔE |
| 构件 | 缺门 / 勒脚 / 檐口 / 拱廊 |

分数低于 84 就把「问题 + 可直接套用的补丁」喂回 AI，让它**只改该改的地方**，
再构建、再体检，最多 3 轮，取分最高的一版。每轮只回传几十行数字，
不重发照片、不重发整份蓝图，token 成本和一轮差不多。

这就是"AI 跑蓝图"：它不手搓方块，它读指标、改蓝图、再验一遍。

### 种子

每次生成会带一个 `seed`（写进蓝图、写进 manifest，界面顶部显示）。
本地构建是确定性的，**同一个种子 + 同一份蓝图 = 同一个模型**，
回填种子就能复刻，也方便把"哪次、多少分"记进经验库。

### 看图：能力按模型分，所以当场测

先纠正一个容易搞错的判断：**视觉能力是"按模型"分的，不是"按厂商"分的**，
而且会随服务端升级悄悄变。同一个端点下实测结果是：

| 模型 | 带图提问 | 不给图 | 结论 |
|---|---|---|---|
| `deepseek-chat` | 读出图里的字 | 明确回答"看不到图" | 有视觉 |
| `deepseek-flash` | 读出图里的字 | 答不出 | 有视觉 |
| `deepseek-v4-pro` | 图片被替换成 `[Unsupported Image]` | 答不出 | 无视觉 |

所以程序里不写死任何判断，而是**发一张写着 `K7Q` 的小图当场测**：
读得出来才算能看图（约 1.5 秒，结果缓存 7 天，换模型或点「重新检测」才重测）。
只看"接口没报错"是不够的 —— 纯文本模型收到图片往往不报错，只是默默丢掉，
然后自信地编。

**默认就用主模型自己看图**，不需要再配第二个模型；「看图能力」里那一栏
只有在你想换成通义 `qwen-vl-max`、智谱 `glm-4v`、豆包、Kimi 之类时才需要填。

流程：

```
照片 ──► 判读（类型/层数/开间/屋面/构件）
              │
              ├──► 层数 × 4.2 米、开间 × 3.6 米  → 真实尺寸（这是绝对尺寸唯一靠谱的来源）
              ▼
         主模型写蓝图 ──► 本地构建 ──► 体检（量测）
                                        │
                                         ▼
                            拼图（原图 | 模型）──► 再看一眼（观感）
                                        │
                                        ▼
                              观感问题 + 量测问题 → 一起喂回去改
```

第二处调用很关键：本地体检只会算比例和密度，算不出"这个孟莎屋顶看起来
像一块压平的板"。把原图和模型渲染拼成一张（`run.py --compare`）再发一次，
就能直接说"屋顶太扁、开间太少、颜色偏青"，而且只花一次读图的钱。

**每一轮都要看图**：看过图的分数是"量测 55% + 观感 45%"，没看的是纯量测，
两者混着排名，最优解会滑向没看过图、分数虚高的那一轮（踩过）。

看图失败不影响主流程：探测不过就退化成纯量测，方案照出，界面上写明
"这个模型读不出图"。

**主体不是建筑时提前止损**：如果判读是 `ship / vehicle / aircraft`，
而看图评分又低于 45，说明构建器没有那套语汇（军舰要船首斜面、甲板收分），
再迭代三轮也只会重新摆一遍方盒子。这时直接停在一轮，把原因写出来。


五个工具：

| 工具 | 作用 |
| --- | --- |
| `photo_brief` | 分析照片，返回体块分段、窗阵节奏、主色（AI 不用看图） |
| `mc_rules` | 返回 MC 建筑设计常识与可选方块清单 |
| `validate_spec` | 按常识校验蓝图，给出 errors / warnings |
| `critique_model` | 构建 + 体检，返回分数、问题清单和可直接套用的补丁（让 AI 自己跑闭环） |
| `build_model` | 按蓝图构建，输出 `.schematic` / 等轴测图 / 查看器 |

### 蓝图格式

```json
{
  "palette": {"wall": "sandstone", "trim": "concrete:7", "roof": "hardened_clay",
              "glass": "stained_glass:11", "accent": "dark_oak_planks"},
  "volumes": [
    {"x":0, "y":0, "z":3, "w":14, "h":8,  "d":10, "mat":"wall", "floors":2,
     "shape":"hex_front"},
    {"x":12,"y":0, "z":0, "w":20, "h":12, "d":13, "mat":"wall", "floors":3,
     "lean":{"x":5,"z":4}}
  ],
  "windows": [{"face":"south","volume":1,"u":2,"v":1,"w":4,"h":3,
               "cols":5,"rows":3,"gap_u":2,"gap_v":1,"mat":"glass","frame":0}],
  "roof":    {"type":"flat","parapet":1,"mat":"roof"},
  "details": [{"type":"balcony","face":"south","volume":1,"u":6,"v":8,"w":8,"depth":1}]
}
```

坐标系与 Minecraft 一致：X 东、Y 上、Z 南，单位是方块。

没有 AI 也能用：

```bash
python run.py --spec 蓝图.json -o output --name 我的楼
```

细节构件按需写，用得最多的几个：

| 构件 | 用在哪 | 主要字段 |
| --- | --- | --- |
| `plinth` / `cornice` | 勒脚、檐口（几乎所有建筑） | `h` / `out` |
| `door` / `portico` | 入口 / 直柱廊门廊 | `u w h` / `w h depth` |
| `bow_portico` | 弧形柱廊（白宫那类） | `u r count col_w h` |
| `grand_stairs` | 山城、宫堡的大台阶 | `u w y1 turns run` |
| `curtain_wall` | 玻璃幕墙（商业立面） | `w h mullion transom` |
| `band` / `louver` / `signbox` | 饰带、竖向格栅、招牌（商业立面） | `u v w h out` |
| `dome` / `spire` | 穹顶、尖顶 | `h style` |

`u` 沿墙面、`v` 从体块底往上、`out` 是往墙外挑几格，单位都是方块。


## 界面

首页是**项目列表 + 方块库**：方块库是全局的（1.12.2 全部可选方块，可搜名称 / 数字 ID / 色值），
点开色块条就能浏览，不占项目页的地方。

进项目之后三个页签：

| 页签 | 干什么 |
| --- | --- |
| 输入工作图片 | 上传四个视角（点选文件、拖拽、或 **Ctrl+V 直接粘贴截图**）、拖尺寸滑条选比例尺（1 米 = 多少格）、让 AI 出蓝图（可直接改），再按蓝图生成 |
| 查看输出结果 | 左侧切模型，中间是模型大图；最上方是醒目的 **3D 查看器**入口，下面是方块清单 |
| 查看仓库内容 | 每次输出一个选项卡（预览图就是模型图）。点开能回看**当时的设定**、**输出时的 AI 蓝图全文**，并下载 `.schematic` / 方块清单 / 逐层平面图 / 蓝图 JSON；右侧可**删除**这次输出（文件同步删除） |

右下角是界面助手**小C**：左键点她弹设置（大小、关闭），她会在生成完成、失败、
第一次打开这些时刻说不同的话。不想要可以关掉，不影响任何功能。

首页右上角是**设置**（`/settings`），左边两个主选项：

| 选项 | 内容 |
| --- | --- |
| 使用说明 | 就是上面这套上手流程，按「开始 / 拍照 / 设置 / AI / 查看器 / 导出 / 方块库 / FAQ」分节 |
| 检测更新 | 当前版本与安装目录 → 检测 GitHub 上有没有新版本 → 一键下载并覆盖安装 |

### 应用内更新怎么做的

更新源是本仓库的 GitHub Release。检查更新读的是仓库里的 `VERSION`
（jsDelivr / raw / API 三个源取最大值，绕开国内直连不通与 60 次/小时限流），
下载用的是 `releases/download/v<版本>/MC12-Studio-v<版本>-win64.zip`。

分两步，任何一步失败都不动现有安装：

1. **暂存**：下载到 `<安装目录>/update/`，用 .NET `ZipFile` 解压（PS 5.1 的
   `Expand-Archive` 会把中文文件名解成乱码），校验有 `runtime/server/index.mjs`、
   包里 `VERSION` 比当前新，才算"就绪"。
2. **覆盖**：写一个纯 ASCII 的批处理到 `%TEMP%`，`start` 成孤儿进程后让页面调用
   `quit_app` 退出。脚本等旧进程死透（8 秒不退就 `taskkill /T /F`），再用
   `robocopy /E` 覆盖，**排除 `projects` / `logs` / `ai.json` / `vision-probe.json`**，
   最后把 exe 重新拉起来。日志写在 `<安装目录>/logs/update.log`。

批处理必须是纯 ASCII：cmd 默认代码页是 936，UTF-8 的中文注释会让整段解析错位。
中文路径与 `MC工程图.exe` 一律作为参数传进去，不写进脚本正文。

## 功能

- **多视角建模**：正/侧/俯/自由四种角色，最多四张；支持拖拽与剪贴板粘贴（Ctrl+V）
- **四套建模语汇**：住宅/古典、商业立面、现代建筑、舰船各有一套体量与构件规则。
  现代建筑按"上下错位的盒子 + 悬挑 + 通高幕墙 + 竖向百叶 + 平顶女儿墙"来写，
  碰到玻璃幕墙的科研楼/办公/美术馆不会再被硬套成孟莎屋顶的府邸；舰船则走尖艏、甲板、栏杆那一套
- **错位体量**：上层体块的 y 接在下层顶面、平面偏 2~6 格，探出下层 2~4 格就是悬挑；
  体块不会被强行等比压扁，宽高比按蓝图换算，层高与宽高比冲突时整体缩放而不是单压高度
- **结构数量可调**：照片里的建筑常由几十个部分组成（角塔、凸窗、侧翼、楼梯间、屋顶设备、烟囱），
  而蓝图只写得到 3~5 个体块。滑条拉到 4~5，构建器会按规则**长出** 20 多个附属体量，
  主体骨架仍按蓝图走 —— 这是"像一栋楼"和"像三个盒子"的分界。附属体量会主动避开入口，
  不会把门廊埋掉
- **大台阶**：`grand_stairs` 贴着立面折返爬升，每级 1 格高、两侧栏墙跟着台阶走成锯齿。
  布达拉宫那种"一圈圈绕上去"的台阶靠它 —— 缺了这一笔，爬在山上的宫殿会变成几摞摆在地上的白盒子
- **弧形柱廊**：`bow_portico` 让柱子沿一段圆弧排开，檐部与顶部栏杆跟着弯（美国白宫南门廊、
  圆厅别墅那一类）。直柱廊加一块顶板，在等轴测里会读成"墙上贴了一块板"
- **斜置体块**：体块可以沿高度倾斜（`lean`，剖面是平行四边形）或沿进深斜切（`skew`，平面是平行四边形），
  **`"lean": {"x": 5, "z": 4}` 是两个方向一起斜**（朝外 + 朝前，照片里最常见的那一种），
  窗、幕墙、百叶、勒脚、女儿墙会跟着斜面走。照片里"上层斜着挑出去"的盒子不再被建成一摞正交方块
- **斜着的楼板（斜带）**：`lean` 只让墙斜，每一层楼板还是水平的 —— 照片里"二层像一条左低右高的带子"
  靠它做不出来。`"tilt": {"axis": "x", "bottom": 8, "top": 8}` 才是**整层斜带**（楼板斜着走），
  只写 `bottom` 是斜底悬挑（盒子方正、底面被斜切），只写 `top` 是斜屋面。
  楼板、女儿墙、檐口、百叶按列自动跟随，幕墙照常写 w/h
- **多边形平面**：一层不一定是个方盒子 —— 六边形实验楼、八边形塔楼、楔形展厅、L 形转角楼、圆塔都能写：
  `"shape": "hex" / "hex_front" / "oct" / "wedge" / "round" / "l"`，或者 `"poly": [[x,z],…]` 自己给顶点，
  `"chamfer": n` 切四角。轮廓会自动变成斜墙，窗、幕墙、檐口、女儿墙、勒脚、楼板全都跟着走，
  窗阵只排在平直墙上（不会顺着 45° 边一路铺到侧墙）
- **形体兜底**：视觉模型判读到"斜"或"六边形平面"、而 AI 写蓝图时漏了，会自动按几何规则补上
  `lean` / `shape`（"修改"时还会把这两个字段钉回去），不再靠模型每次记得写
- **配色跟随照片**：线脚是墙色的派生色（压暗一档），不会因为 AI 挑了个深色就把整栋白楼染成青灰
- **尺寸即细节**：xs/s 只保证体块与门窗，m 起补腰线，l/xl 会要求更多体块、幕墙、阳台与屋顶设备
- **装饰替代**：先把画面分割成天空 / 植被 / 草坪 / 建筑 / 栅栏区，确认某块不是建筑之后，才用树叶、栅栏这类装饰方块堆叠替代它（而不是逐格猜材质）
- **体块组合**：屋顶线出现台阶时，把较矮的一段当作缩进去的侧翼，平面自然成 L 形或 T 形，而不是一块平板
- **屋顶收头**：默认沿屋顶线压一圈女儿墙；要坡屋顶可以显式指定双坡或四坡，按高度逐层收
- **一键出模型**：照片 → 透视矫正 → 光照归一化 → 降采样到 1 像素 = 1 方块 → 配色 → 体素化 → 空心壳
- **方块表**：按数量排序的方块清单，直接对着清单备料
- **三种预览**：等轴测渲染图、HTML 三维查看器、逐层平面图
- **项目化管理**：每个项目独立文件夹，可命名、记录创建时间，随时切回继续改图
- **界面助手「小C」**：右下角的 Q 版角色，会呼吸、眨眼、摆腿、跟着鼠标看；
  点一下能调大小或关掉。她会按事件说不同的话（生成完成、失败、第一次打开），安静但不冷淡
- **桌面版**：不依赖浏览器，双击 exe 即开原生窗口；磁盘上的项目文件夹改动会自动同步回界面
- **旧版本兼容**：只用 1.12.2 存在的方块（数字 ID + metadata），导出的 `.schematic` 可直接丢进 WorldEdit / MCEdit

## 快速开始

### 桌面版（推荐）

双击 `启动界面.bat`。首次运行会自动装前端依赖、构建并组装发布包（约两三分钟），之后直接开窗口。

产物在 `dist/MC工程图/`，其中 `MC工程图.exe` 可单独拷走使用，不需要另装 Python 或 Node。

### 从源码跑

```bash
# 1. 前端依赖
cd web && npm install

# 2. 后端依赖（Python 3.10+，需要 numpy 与 Pillow）
pip install numpy pillow pywebview

# 3. 开发模式（Nuxt 热更新，浏览器访问 http://localhost:4310）
cd web && npm run dev
```

回到项目根目录执行 `python run.py` 是本项目的命令行入口，也是后端进程的实际工作方式。

### 命令行

```bash
python run.py --spec 蓝图.json -o output --name 我的楼   # 按蓝图构建
python run.py --brief -i 正视图.jpg --width 40            # 只做分析，输出 brief
python run.py --rules                                    # 打印建筑设计规则
python run.py --mcp                                      # 以 MCP 服务运行
```

| 参数 | 说明 |
| --- | --- |
| `--spec` | 蓝图 JSON，唯一的构建入口 |
| `--brief -i 照片` | 照片分析，打印 brief（给 AI 用） |
| `--width` | `--brief` 时按多少格宽分析，默认 40 |
| `-o` / `--name` | 输出目录 / 模型名 |

完整参数见 `python run.py -h`。

> 0.17.0 起删掉了「照片直转体素」的旧路线（synth / building / hall / relief / flat / terrain）。
> 实测同一栋别墅：旧路线输出的是一栋绿色方盒子（墙色被树下阴影带成绿色混凝土），
> 或一张照片浮雕；AI 蓝图路线能给出双体块、门、幕墙、阳台与檐口。

> **关于装饰替代的做法**：不是逐格判断"这块像不像树叶"，而是先做场景分割（`mc12/scene.py`）——分出天空、植被、草坪、建筑、栅栏区，确认某块区域不属于建筑之后，才用装饰方块去替代。窗框永远不会变成栅栏，因为它在建筑里面，进不了栅栏区。书架属于室内家具，不在这个分类里，要 `--decor all` 才启用。另外栅栏在 1.12 是非整方块（高 1.5 格、可穿过），导入后的观感与整方块不同。

## 目录结构

```
mc12/         建模核心：蓝图展开、体素化、配色、schematic 导出、查看器
pack/         桌面外壳（pywebview + WebView2）与发布包构建脚本
web/          Nuxt 4 前端 + Nitro 后端（项目库、AI 方案、仓库与修改）
tools/        辅助脚本：方块库导出、查看器模板升级、体检/对比
run.py        命令行入口 / 后端进程（`--mcp` 时作为 MCP 服务）
mcp_server.py MCP 工具定义（photo_brief / mc_rules / validate_spec / build_model）
```

## 打包发布
